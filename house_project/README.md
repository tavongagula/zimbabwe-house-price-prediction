# Zimbabwe House Asking-Price Prediction

## Project question

**Which features explain the asking prices of houses for sale in Zimbabwe, and how accurately can a model predict them?**

This repository collects public property listings, cleans and explores the data, extracts image and text representations, and compares eight models for predicting the natural logarithm of house asking price.

## 2. Software requirements

Use Python 3.10 or 3.11 in a virtual environment. The project uses:

- pandas, NumPy and Matplotlib for data handling and plots;
- SciPy and scikit-learn for statistics and classical machine-learning models;
- PyTorch for the neural networks;
- torchvision / a pretrained ResNet-50 for image feature extraction;
- sentence-transformers for the `all-MiniLM-L6-v2` text embeddings;
- Pillow for image handling;
- requests and BeautifulSoup (if required by the scraper).

Install the dependencies from the project root. Create a `requirements.txt` containing the packages actually imported by the submitted scripts and notebooks. A starting list is:

Open PowerShell in the project folder (the folder containing this README).

```powershell

.\.venv\Scripts\Activate.ps1

pip install -r requirements.txt

# Register this environment as a Jupyter kernel
python -m ipykernel install --user --name zim-house-price --display-name "Python (Zim House Price)"
```

If PowerShell blocks environment activation, use:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

Then start Jupyter:

```powershell

```

In each notebook, select the kernel **Python (Zim House Price)**.

## 4. Run order

Run the notebooks from the project root, in the order below. Run every cell from top to bottom.

### Step 1 — Collect the listings (only if permitted / needed)

```powershell
python property_scraper.py
```

The scraper should create the raw listing CSV and the photo index in the location configured in that script (the cleaning notebook expects `zim_property_data/listings.csv` and optionally `zim_property_data/image_index.csv`).

The submitted dataset was collected on 22–25 November 2026. For assessment, the supplied CSV and feature files should be used rather than re-scraping the website. Re-scraping may produce different listings, changed prices, removed adverts or different images. Do not run the scraper unless you have checked the website's current terms and collection permissions. Respect robots.txt, request delays and any access restrictions.

### Step 2 — Clean and explore

Open and run:

`notebooks/02_cleaning_and_exploration.ipynb`

This notebook reads `zim_property_data/listings.csv` (or `data/listings_raw.csv` if the former is absent), removes duplicates, applies the cleaning rules and writes outputs including:

- `data/listings_raw.csv`
- `data/all_listings_deduped.csv`
- `data/houses_clean.csv`
- `figures/` exploratory plots
- `tables/` summary and cleaning-log CSV files

The modelling dataset should contain 2,283 houses, matching the reported analysis. If it does not, check that you are using the supplied original dataset and the same notebook settings.

### Step 3 — Extract photo and text features

From the project root, run:

```powershell
python extract_features.py
```

This step is required before running the modelling notebook unless the precomputed feature files are already supplied. It should create:

- `data/image_features.npz` — image feature vectors indexed by `listing_id`;
- `data/text_features.npz` — text feature vectors indexed by `listing_id`.

The image features are based on a frozen pretrained ResNet-50; the text features use `all-MiniLM-L6-v2`. The modelling notebook expects these exact file names and aligns features to houses using `listing_id`.

The helper module `text_utils.py` must be in the project root because the modelling notebook imports `mask_prices` and `leaks_price` from it.

### Step 4 — Fit and evaluate the models

Open and run:

`notebooks/03_models.ipynb`

Set `QUICK = False` in the settings cell for the full reported experiment. This runs the five-seed neural-network test models and five-fold cross-validation. It can take substantially longer than the cleaning notebook.

For a short functionality check only, set `QUICK = True`. This reduces the number of seeds and skips cross-validation; **do not use QUICK-mode results as the final reported results**.

The notebook expects these files to exist before it starts:

- `data/houses_clean.csv`
- `data/image_features.npz`
- `data/text_features.npz`
- root-level `text_utils.py`

It writes model comparison, cross-validation, error-analysis and feature-importance tables to `tables/`, plots to `figures/`, and test predictions to `data/test_predictions.csv`.

### Step 5 — Optional repository photo copies

If your project uses `make_repo_images.py` to create smaller copies for the submission, run:

```powershell
python make_repo_images.py
```

Check the script's configured input and output folders before running it. The final `images/` folder must contain image files named exactly with the corresponding `listing_id` (for example `images/123456.jpg`). The ID in the filename must match the `listing_id` value in the CSV. Do not rename IDs or use arbitrary filenames.

## 5. Reproducing the reported results

## 6. Data and file notes

- `listing_id` is the key linking a listing row to its image file and saved feature vectors.
- `price_usd` is the asking price in US dollars.
- `log_price` is the natural logarithm of `price_usd`, the model target.
- `houses_clean.csv` contains the cleaned house modelling set; other property types are not included in this modelling file.
- `image_features.npz` and `text_features.npz` are NumPy compressed archives. Keep them as `.npz` files; do not open and resave them as CSV.
- `figures/` and `tables/` contain generated outputs. They can be regenerated by running the notebooks.
- The report is limited to six pages and summarises the final experiment.

See `DATA_DICTIONARY.md` for field definitions. The data dictionary must be checked against the actual CSV headers before submission.
